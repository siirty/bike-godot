# Security Policy

## Reporting a vulnerability

Do not open a public issue containing exploit details, secrets, personal data, or sensitive logs.

Configure a private reporting channel before releasing the project publicly, then replace this section with the exact contact or GitHub private-vulnerability-reporting instructions.

Include:

- affected version or commit;
- reproducible impact and prerequisites;
- minimal proof of concept with secrets removed;
- suggested mitigation when known.

## AI-assisted changes

AI-generated or AI-reviewed code receives the same security requirements as human-authored code. Model review is advisory and does not replace dependency scanning, secret scanning, static analysis, threat modeling, or qualified human review for sensitive changes.
